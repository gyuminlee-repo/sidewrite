# 보안과 개인 정보

Sidewrite 는 내 컴퓨터에서 내가 쓰는 1인용 도구다. 위협 모델은 "내 컴퓨터, 내 문서" 이고 강화된 서비스가 아니다.

## 알아 둘 것

- **열린 Office 파일 쓰기 거부는 사고 방지 장치다.** 정규식 기반이라 작정한 에이전트는 우회할 수 있다(문자열로 조립한 경로, 디코딩한 내용). 열린 Office 파일을 실수로 덮어쓰는 일을 막는다. Office 파일은 `office_*` / `excel_*` 도구로 고친다.
- **로컬 bridge 는 loopback 전용이고 token 이 필요하다.** WebSocket 은 `127.0.0.1` 에만 묶이고 daemon 마다 token 을 요구한다. CORS 가 브라우저의 교차 출처 읽기를 막는다. 같은 사용자로 도는 로컬 프로세스는 token 을 읽을 수 있다. 악성 로컬 프로세스는 범위 밖이다.
- **대화 기록은 가리지 않고 디스크에 남는다.** Agent SDK 는 세션마다 전체 기록을 `~/.claude/projects/<hash>/<session_id>.jsonl` 에 쓴다. 도구 입출력이 들어 있어 문서 텍스트와 에이전트가 읽은 파일 내용이 포함될 수 있다. `daemon.log` 에도 채팅 메시지가 평문으로 남는다. 두 곳 모두 민감 정보로 다루고 기록을 지우려면 삭제한다.
- **워크스페이스와 `~/.claude` 에 쓴다.** context 파일은 워크스페이스 `CLAUDE.md` 에 경로만 기록된다. 그 밖의 폴더는 문서 도구를 거칠 때만 바뀐다. 리비전 흐름이 원고 옆에 쓰는 파일은 [원고 옆에 생기는 파일](files.md) 에 있다.
- **문서 내용은 Anthropic API 로 간다.** 답하려면 모델이 관련 문서 텍스트(와 읽은 context 파일)를 봐야 한다. 터미널의 Claude Code 와 같은 신뢰 경계다. 조율, 파일 접근, 도구 실행은 로컬에 머문다.

## API key

- provider key 는 `~/.claude/office-addins/provider-keys.json` (권한 0600)에 저장되거나 `CC_OFFICE_KEY_<ID>` 환경 변수에서 온다.
- key 는 작업창과 로그에 나오지 않는다.
- Gemini API 무료 등급 입력은 Google 제품 개선에 쓰이고 사람이 읽을 수 있다. provider 목록이 이 정책을 보여 준다.

## figures 페이지

figures 페이지는 이 컴퓨터에서만, 실행 중인 daemon 의 token 으로만, 연결된 Word 작업창에 열린 원고에 대해서만 답한다. 지정한 그림 파일은 읽기만 한다.

## 배포

이 저장소는 오픈 소스다. 각 사용자가 자기 컴퓨터에서 자기 인증으로 클론해 돌린다. 한 구독을 여러 사용자가 나눠 쓰는 호스팅 서비스는 허용되지 않는다.
